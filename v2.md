# Batch Ascent V2 - Release Notes

## 🚀 New Features & Enhancements

### 1. Advanced Role-Based Access Control (RBAC)
We have implemented granular permissions for managing student data, ensuring data security and operational efficiency.

*   **Email Editing:**
    *   **Admin & CEO:** Can edit email addresses for *all* students.
    *   **Sales Heads, SHO, SSHO:** Can edit email addresses for students within batches belonging to their specific **School**.
    *   **Sales Persons:** Can *only* edit email addresses for students assigned to their specific **Sales ID**.
    *   *Note:* Updates are synchronized across both the enrollment (`student_batches`) and official records (`students` table).

*   **Student Verification:**
    *   **Authorized Roles:** Only **Sales Heads** (matching the batch's school), **Admins**, and **CEOs** can verify students.
    *   **Restriction:** `SHO` and `SSHO` roles do **not** have verification privileges.

### 2. Enhanced Student Workflow
A clearer, status-driven workflow for managing student enrollments.

*   **Status Indicators:** Visual badges for every stage:
    *   🟠 **Pending Verification**: Default state for new manual enrollments.
    *   🔵 **To Call**: Verified students waiting for a welcome call.
    *   🟡 **Pending Onboard**: Called but not yet marked as fully onboarded.
    *   🟢 **Onboarded**: Successfully enrolled and active.

*   **Verification System:**
    *   "Verify Now" button allows authorized leaders to confirm student enrollments.
    *   Records a timestamp (`verified_at`) for audit trails.

*   **Call Management:**
    *   **Direct Dialing:** Clicking "Call Student" now immediately opens the device's default dialer.
    *   **Undo Capability:** Added an "Accidentally clicked? Undo Call" option to revert the status if a call is logged by mistake.

### 3. Application Stability & Fixes

*   **Login System:**
    *   **Duplicate Handling:** Fixed an issue where duplicate email records caused login failures. The system now safely handles these cases.
    *   **Auto-Recovery:** Automatically generates missing Sales IDs for Sales users upon login if phone number is present/provided.

*   **Batch Management:**
    *   **ID Sanitization:** The "Create Batch" form now strictly enforces alphanumeric characters (plus hyphens/underscores) for Batch IDs.
    *   **404 Prevention:** This prevents special characters (like slashes) from breaking URL routing and causing 404 errors on batch detail pages.

*   **Technical Improvements:**
    *   Resolved `Next.js` hydration mismatch errors caused by browser extensions.
    *   Refactored code structure for better maintainability.
